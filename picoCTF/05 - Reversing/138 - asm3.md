## Descripción
What does asm3(0xcc000a09,0xcdb0b591,0xc1116756) return? Submit the flag as a hexadecimal value (starting with '0x').

## Solución
- Analizamos el código ensamblador x86 (sintaxis Intel de 32 bits) de la función `asm3`:
  ```assembly
  asm3:
  	<+0>:	push   ebp
  	<+1>:	mov    ebp,esp
  	<+3>:	xor    eax,eax
  	<+5>:	mov    ah,BYTE PTR [ebp+0xb]
  	<+8>:	shl    ax,0x10
  	<+12>:	sub    al,BYTE PTR [ebp+0xe]
  	<+15>:	add    ah,BYTE PTR [ebp+0xf]
  	<+18>:	xor    ax,WORD PTR [ebp+0x12]
  	<+22>:	nop
  	<+23>:	pop    ebp
  	<+24>:	ret
  ```
- En la convención de llamadas cdecl de 32 bits, los argumentos se apilan de derecha a izquierda:
  - `[ebp+0x8]` $\rightarrow$ Argumento 1: `0xcc000a09`
  - `[ebp+0xc]` $\rightarrow$ Argumento 2: `0xcdb0b591`
  - `[ebp+0x10]` $\rightarrow$ Argumento 3: `0xc1116756`
- Distribución de bytes en memoria (formato Little-Endian):
  | Desplazamiento | Byte en hexadecimal | Argumento correspondiente |
  | :--- | :--- | :--- |
  | `[ebp+0x8]` | `0x09` | Arg 1 (byte 0) |
  | `[ebp+0x9]` | `0x0a` | Arg 1 (byte 1) |
  | `[ebp+0xa]` | `0x00` | Arg 1 (byte 2) |
  | `[ebp+0xb]` | `0xcc` | Arg 1 (byte 3) |
  | `[ebp+0xc]` | `0x91` | Arg 2 (byte 0) |
  | `[ebp+0xd]` | `0xb5` | Arg 2 (byte 1) |
  | `[ebp+0xe]` | `0xb0` | Arg 2 (byte 2) |
  | `[ebp+0xf]` | `0xcd` | Arg 2 (byte 3) |
  | `[ebp+0x10]` | `0x56` | Arg 3 (byte 0) |
  | `[ebp+0x11]` | `0x67` | Arg 3 (byte 1) |
  | `[ebp+0x12]` | `0x11` | Arg 3 (byte 2) |
  | `[ebp+0x13]` | `0xc1` | Arg 3 (byte 3) |

- Ejecución paso a paso:
  1. `<+3>: xor eax, eax` $\rightarrow$ `eax = 0x00000000`.
  2. `<+5>: mov ah, BYTE PTR [ebp+0xb]`
     - El byte en `[ebp+0xb]` es `0xcc`.
     - `ah = 0xcc` $\implies$ `ax = 0xcc00`.
  3. `<+8>: shl ax, 0x10`
     - En x86 de 32 bits, el operando destino es el registro de 16 bits `ax`.
     - Desplazar a la izquierda 16 bits (`0x10`) un registro de 16 bits provoca que todos sus bits se desplacen fuera del registro:
       $$\text{ax} = (0xcc00 \ll 16) \pmod{2^{16}} = 0x0000$$
  4. `<+12>: sub al, BYTE PTR [ebp+0xe]`
     - El byte en `[ebp+0xe]` es `0xb0`.
     - `al = 0x00 - 0xb0 = 0x50` (aritmética módulo 256: $256 - 176 = 80 = 0x50$).
     - Por lo tanto, `ax = 0x0050`.
  5. `<+15>: add ah, BYTE PTR [ebp+0xf]`
     - El byte en `[ebp+0xf]` es `0xcd`.
     - `ah = 0x00 + 0xcd = 0xcd`.
     - Por lo tanto, `ax = 0xcd50`.
  6. `<+18>: xor ax, WORD PTR [ebp+0x12]`
     - La palabra (16 bits) a partir de `[ebp+0x12]` en Little-Endian está compuesta por los bytes en `0x12` (`0x11`) y `0x13` (`0xc1`), lo que equivale a `0xc111`.
     - Operación XOR a 16 bits:
       $$\text{ax} = 0xcd50 \oplus 0xc111 = 0x0c41$$
  7. `<+22> a <+24>`: `nop`, `pop ebp`, `ret`.
     - La función retorna el valor almacenado en `eax` / `ax`: `0xc41`.

- Valor de retorno en hexadecimal:
```text
0xc41
```

## Notas Adicionales
- En arquitecturas x86 (IA-32), la representación de enteros multinivel en memoria sigue el orden Little-Endian (el byte de menor peso se almacena en la dirección más baja).
- Desplazamientos como `shl ax, 0x10` operan sobre el tamaño del registro especificado (`ax` es de 16 bits, a diferencia de `eax` que es de 32 bits), lo que resulta en la pérdida completa de los bits existentes en `ax`.
- Herramientas utilizadas:
  - NASM (`nasm -f elf32`) y GNU `ld` para ensamblar y verificar la ejecución nativa de 32 bits.
  - Script en Python para mapeo de memoria y simulación de instrucciones.
